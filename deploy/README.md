# Universal Cloud Migration & Server Portability Guide

The NBPDCL Meter Billing & Management System features a **zero-vendor-lock-in** universal migration engine. You can move the entire application, database, and asset storage across any cloud provider (AWS, DigitalOcean, Hetzner, Hostinger, GCP, Linode, or on-premise) across **3 distinct deployment types**:

---

## 3 Deployment Types

| Deployment Type | Environment | Typical Hosts | Root / SSH Needed? | Web UI Restore? |
| :--- | :--- | :--- | :--- | :--- |
| **Type 1: Shared Hosting** | Apache / LiteSpeed, cPanel / Plesk, PHP 8.3/8.4 | Hostinger, Bluehost, Namecheap | ❌ No | ✅ Yes (Web UI Chunked) |
| **Type 2: Docker Stack** | Docker Engine + Docker Compose | DigitalOcean Droplet, AWS EC2, GCP Compute | ❌ Containerized | ✅ CLI & Web UI |
| **Type 3: Native VPS** | Ubuntu 22.04/24.04 bare-metal (Nginx + PHP 8.4-FPM + MySQL 8 + Redis 7) | DigitalOcean, Hetzner, AWS, Linode | ✅ Root required for provisioner | ✅ CLI & Web UI |

---

## Cross-Type Bundle Compatibility

Every migration bundle generated by:
- Web Admin Panel: **Admin > Cloud Migration & Portability > Generate & Download**
- CLI: `php artisan app:migration-pack`

produces a single, self-contained, standard `.zip` file containing:
1. `manifest.json`: Metadata, app version, SHA-256 checksums, financial ledger checksum (`wallets.balance`), and exact table row counts across 13 core tables.
2. `database.sql.gz`: Gzip-compressed atomic MySQL dump with `SET FOREIGN_KEY_CHECKS=0`.
3. `storage.zip`: Compressed archive of all bill PDFs, photos, and public storage assets.

Any bundle generated on **Type 1** can be restored on **Type 2** or **Type 3**, and vice-versa, with 100% data fidelity.

---

## Restoring on Type 1 (Shared Hosting / Hostinger)

1. Upload your code files to `public_html/`.
2. Configure `.env` with your database credentials and identical `APP_KEY`.
3. Log in as an Administrator (`/login`).
4. Go to **Admin > Cloud Migration & Portability**.
5. Verify that **Server Health & Migration Readiness** is green.
6. Under **Import & Rehydrate Server**, upload your `.zip` bundle and click **Restore & Execute Verification Audit**.
7. The system unpacks the database, verifies SHA-256 signatures, rehydrates storage, and audits row counts.

---

## Restoring on Type 2 (Docker Compose)

1. Clone or copy the project code onto the destination server.
2. Copy `.env.docker.example` to `.env` and set `APP_KEY` matching the source server.
3. Start the containers:
   ```bash
   docker compose up -d --build
   ```
4. Copy your migration bundle into the container:
   ```bash
   docker compose cp /path/to/migration-xxxx.zip app:/var/www/html/storage/app/migrations/
   ```
5. Run the restore command inside the container:
   ```bash
   docker compose exec app php artisan app:migration-unpack storage/app/migrations/migration-xxxx.zip
   ```

---

## Restoring on Type 3 (Native Ubuntu VPS)

1. Provision the clean Ubuntu 22.04/24.04 VPS using the automated provisioner:
   ```bash
   curl -sSL https://raw.githubusercontent.com/shamim244/meter-billing-management/main/deploy/vps-provision.sh | sudo bash
   ```
   *(Or run `sudo bash deploy/vps-provision.sh` from the cloned repository).*
2. Copy your code into `/var/www/meter-billing`.
3. Copy your migration bundle into `/var/www/meter-billing/storage/app/migrations/`.
4. Run the unpack command:
   ```bash
   cd /var/www/meter-billing
   sudo -u www-data php artisan app:migration-unpack storage/app/migrations/migration-xxxx.zip
   ```
5. Restart services:
   ```bash
   sudo systemctl restart meter-billing-queue.service
   sudo systemctl reload nginx
   ```

## Mobile App Resilience (Flutter Endpoint Discovery)

When a server is migrated to a new IP or domain, existing Flutter mobile apps in the field automatically discover the updated server endpoint via:

```http
GET /api/v1/app/config
```

The response includes:
- `primary_endpoint`: Active base URL.
- `fallback_endpoints`: Alternate failover servers / domains.
- `qr_connect`: QR payload for rapid pairing without manual typing.
- `min_supported_version` & `latest_version`: Automatic update enforcement.
